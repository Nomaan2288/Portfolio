Section 01

Industry Problem & Architectural Scope

Out-of-Home (OOH) advertising—specifically roadside billboards, digital hoarding screens, and transit displays—remains a multi-billion dollar sector plagued by archaic offline workflows. Historically, brands and marketing agencies negotiate billboard leases through endless phone calls, physical paper agreements, and manual spreadsheets.

This traditional process suffers from three catastrophic vulnerabilities: double-booked calendar slots, lack of transparent geospatial pricing, and untracked reconciliation between campaigns and invoice ledgers.

SpotAdz was architected as a programmatic, centralized B2B media marketplace that bridges outdoor billboard property owners with corporate advertisers. Built from the ground up on Java Spring Boot and MySQL, the platform enforces programmatic availability verification, automated B2B invoicing, and multi-tenant operational pipelines.

Core Engineering Objective
Eliminate calendar reservation collisions across multi-week commercial billboard bookings, automate commercial tax/GST invoice generation, and partition advertiser assets from media owner operations via strict role-based access boundaries.

Section 05

Collision-Free Date-Range Scheduling Algorithm

Unlike movie tickets that represent a point-in-time slot (e.g. 7:00 PM on Friday), billboard campaigns span date intervals (e.g. October 1st to November 15th). The core algorithmic challenge is preventing any overlapping reservation for the same physical billboard board during any single intersecting day.

To prevent calendar overlap, SpotAdz executes an interval collision query at the persistence boundary:

ReservationService.java — Overlap Detection Query MySQL 8.0
// Mathematical condition for two date ranges [A, B] and [X, Y] colliding:
// (StartA <= EndB) AND (EndA >= StartB)

SELECT COUNT(*) FROM billboard_bookings
WHERE billboard_id = :boardId
  AND booking_status IN ('CONFIRMED', 'ACTIVE', 'HOLD')
  AND start_date <= :requestedEndDate
  AND end_date >= :requestedStartDate;

Section 09

Key Architectural Lessons & Future Horizons

Developing SpotAdz reinforced key distributed engineering patterns for commercial marketplaces:

1. Interval Queries Demand Compound Date Indexing
Filtering by `(billboard_id, start_date, end_date)` with status predicates requires careful multi-column composite indexing in MySQL InnoDB. Without an index on `(billboard_id, booking_status, start_date, end_date)`, checking availability during high-traffic booking surges degrades into full table scans.
2. Explicit State Machines Prevent Invalid Business Transitions
Using a strict state machine ensures no campaign can leap directly from 'Draft' to 'Live' without passing through payment verification and creative asset compliance, protecting both media owners and advertisers.
